# bench/keccak — Keccak-f[1600], first-party

Written in this repository for the doc-18 round-26 three-tier measurement. **Not
third-party RTL** — unlike the rest of `bench/`, this one is ours and is committed, so
the load-bearing measurement can be reproduced. FIPS 202, one permutation round per
clock, 1600-bit flat port.

| file | what |
|---|---|
| `keccak_f.sv` | the readable core — a `rho` offset table and a `rotl64` as user functions |
| `keccak_f_arr.sv` | same, but `rho` builds a 25-element `integer` array on every call |
| `keccak_f_flat.sv` | GENERATED by `gen_flat.py` — every call expanded inline |
| `tb.sv` | chains `+N=<count>` permutations and prints two lanes plus their xor |

`keccak_f.sv` and `keccak_f_arr.sv` differ ONLY in how `rho` looks up a constant, and
that one difference is worth 2.3x in vita (doc-18 round-26 §3). `keccak_f_flat.sv`
exists because a process containing a `Terminator::Call` is refused by
`backend::is_codegen_able`, so the flat form is the only way to measure what the
bytecode VM would be worth on this design.

## Oracle

Four independent implementations agree on every `N`: a Python reference, vita, iverilog
13, and verilator 5.050. The all-zero-state first lane is the published Keccak value
`f1258f7940e1dde7`, so the agreement is anchored, not merely mutual.

```bash
vita                  tb.sv keccak_f.sv +N=200
vita --backend interp tb.sv keccak_f.sv +N=200     # VM contribution A/B
iverilog -g2012 -o k.vvp tb.sv keccak_f.sv && vvp k.vvp +N=200
verilator --binary --timing -Wno-fatal -o vk tb.sv keccak_f.sv && ./obj_dir/vk +N=200000
```
