# bench/keccak — workload corpus recipe

First-party (see `README.md`). Two corpus rows share this directory because the two
designs differ in exactly one thing.

| | |
|---|---|
| Origin | written in this repository, committed |
| Oracle | iverilog 13.0, verilator 5.050 **and** a Python reference all agree |
| Anchor | the all-zero-state first lane is the published Keccak value `f1258f7940e1dde7`, so the agreement is anchored rather than merely mutual |
| Expected | `perms=2000 lane0=54aa20c46ef0e0f6 lane1=b19e9f995e1f41d3 acc=767c5ab6776c4bde` (both rows) |

## Commands (from `bench/keccak/`)

```sh
iverilog -g2012 -o keccak.vvp     tb.sv keccak_f.sv     && vvp keccak.vvp     +N=2000
iverilog -g2012 -o keccak-arr.vvp tb.sv keccak_f_arr.sv && vvp keccak-arr.vvp +N=2000
../../target/release/vita tb.sv keccak_f.sv     +N=2000
../../target/release/vita tb.sv keccak_f_arr.sv +N=2000
```

## Timings (2026-08-23, macOS arm64, interleaved, first round discarded)

| row | design | iverilog | vita | ratio |
|---|---|---|---|---|
| `keccak` | `keccak_f.sv` | 9.295 s | 8.426 s | 1.10x faster |
| `keccak-arr` | `keccak_f_arr.sv` | 9.169 s | 17.237 s | **0.53x — the corpus worst case** |

Three timed samples, interleaved, first round discarded. The cross-corpus table is
`docs/study/03-workload-corpus.md`.

`keccak_f_arr.sv` differs from `keccak_f.sv` ONLY in how `rho` looks up a constant: it
builds a 25-element `integer` array on every call. That one difference is worth 2.0x,
and every arena estimate this project has made (6-10 weeks, ceiling 2.33x) was
computed from this row alone. That is exactly why the rest of the corpus exists.

`keccak_f_flat.sv` (generated by `gen_flat.py`) is not a corpus row: it exists to
measure what the bytecode VM would be worth on a body containing no `Terminator::Call`.
