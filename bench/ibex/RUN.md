# bench/ibex — lowRISC Ibex, the corpus's SystemVerilog core

The corpus row `ibex`: lowRISC's Ibex RV32 core, instantiated through `ibex_top`, runs a
15-instruction RV32IM loop from a testbench memory. The run is reduced to one `DIGEST=`
line. It is the corpus's only SystemVerilog design: packages, packed structs, enums,
`generate` blocks, assertion macros and 30,272 lines of upstream RTL. It is also the
only row whose oracle is verilator, because iverilog 13 cannot parse it. A second,
4-state oracle agrees with verilator: sv2v converts the design to Verilog, and iverilog
runs the result.

vita refuses it today (`Expect::Refused`). The row measures the distance to running it,
one error class at a time; see "vita today" below.

## Commands (from `bench/ibex/`)

```sh
F=$(cat files.txt)            # /bin/sh — zsh does not word-split $F
D="-DSYNTHESIS -DDV_FCOV_DISABLE"
I="-Isrc/vendor/lowrisc_ip/ip/prim/rtl -Isrc/vendor/lowrisc_ip/dv/sv/dv_utils -Isrc/rtl"

# vita
../../target/release/vita --top tb $D $I $F +N=20000

# verilator (the oracle)
verilator --binary --timing -Wno-fatal -Wno-lint -Wno-style -j 0 -o v --top-module tb $D $I $F
./obj_dir/v +N=20000

# iverilog (cannot parse it, see below)
iverilog -g2012 -s tb $D $I -o ibex.vvp $F
```

`./run.sh vita`, `./run.sh verilator`, `./run.sh verilator-x` (the x check below),
`./run.sh sv2v` (the 4-state cross-check below; needs `sv2v` on `PATH`) and
`./run.sh iverilog` wrap these. The iteration count can be overridden as
`N=<iterations> ./run.sh …`.

## What the workload exercises

`ibex_top` is configured with `RV32M=RV32MFast` (a 3–4 cycle multiplier and an iterative divider),
`RV32B=RV32BNone`, `RegFile=RegFileFF`, no branch-target ALU, no writeback stage, no
icache and no security hardening. Boot address is 0, so the core fetches from 0x80.
The program loads N from 0x400 and loops N times over add, shift-left, xor, `mul`,
shift-right and add, storing the accumulator to 0x700 every iteration. It then stores
the accumulator to 0x404. That store is the sentinel: the testbench prints the digest
and calls `$finish`.

Reset is asserted by a falling edge of `rst_n` at 1 ns, held for ten rising edges, and
released on a falling edge. The asserting edge matters: ibex's core runs on a gated
clock whose enable (`ibex_top.sv:325`) is state the reset itself clears, so a reset that
waited for clock edges could miss the core entirely (see the x check below). The release
is on a falling edge because a blocking release at a rising edge races every flop that
samples `rst_n` there. The four inputs this configuration does not use
(`scramble_key_i`, `scramble_nonce_i`, `ram_cfg_icache_{tag,data}_i`) are tied to 0
rather than left open, because an open input is z in a 4-state simulator and 0 in
verilator. The memory process is a plain `always`: the initial block also writes `mem`,
and a variable an `always_ff` writes may have no other writer (IEEE 1800-2017
§9.2.2.4).

The testbench memory answers both ports in one cycle, with no wait states and no bus
errors. The digest updates every cycle after reset. It rotates left by one, then XORs in
the fetch and data addresses (each zero when its request is low), a control byte holding
both request strobes, the write strobe and the byte enables of every data request, loads
included, and the cycle count. It adds the byte enables and write data of every store.
The cycle count is what makes an idle cycle visible: without it, idle cycles before the
first request rotate a zero digest, and 64 idle cycles are a full rotation. One gap is
left, measured by the review: when the sentinel lands on a cycle count divisible by 64 —
`+N` ≡ 38 (mod 64) — a stall of the whole bus for a multiple of 128 cycles after the last
store leaves the digest unchanged. The pinned sizes land elsewhere (`+N=2000` and
`+N=20000`), and there no whole-bus stall up to 524,288 cycles is invisible. Nothing
before the reset release is observed. Final state is never compared. A 20 ms watchdog
prints `WATCHDOG` and a fixed digest if the sentinel never arrives. It is fixed, not
scaled: the sentinel arrives near 150·N ns, so above about `+N=133000` a healthy run
prints `WATCHDOG` too.

## The oracle is verilator, under one condition

Contract rule 2 names iverilog as the reference. iverilog 13 stops at the first package:

```
src/rtl/ibex_pkg.sv:350: syntax error
I give up.
```

Line 350 initialises a packed-struct `localparam` with a keyed assignment pattern
(`'{irq_ext: 1'b1, irq_int: 1'b0, lower_cause: 5'd03}`). That is legal SystemVerilog
(IEEE 1800-2017 §10.9.2).

verilator is 2-state, so it answers for a design whose digest does not depend on x.
It does not answer for one whose digest does: `picorv32` and `serv` read uninitialised
state, and verilator's digests for them belong to a different design. The row is
admitted only because its digest is x-invariant. `./run.sh verilator-x` rebuilds with
`--x-assign unique --x-initial unique` and runs 66 times:

| run-time option | `+N=20000` | `+N=2000` |
|---|---|---|
| `+verilator+rand+reset+0` (all zeros) and `+1` (all ones) | `13b2ddfcd551ba2f` | `32e0e78741376133` |
| `+verilator+rand+reset+2`, seeds 1–64 (`+N=2000`: seeds 1–100) | `13b2ddfcd551ba2f`, all 64 | `32e0e78741376133`, all 100 |
| the same build with `--x-initial-edge`, `+rand+reset+0`, `+1`, seeds 1–32 | `13b2ddfcd551ba2f`, all 34 | — |

A few seeds do not show this. The first version of this testbench declared
`logic rst_n = 1'b0` and never drove a falling edge, so the core's flops saw reset only
through its gated clock, whose enable is itself reset state. It printed the pin for
`+rand+reset+0`, `+1` and five seeds, yet over seeds 1–60, 77 and 12345, 29 of 62 runs
did not print it: 27 ended in `WATCHDOG` and 2 printed other digests. That version had
passed its x check by luck, and the review measured the failure. The asserting edge fixed
it, and 66 runs is the check now. On this testbench the review ran 770 more — seeds
101–600 at `+N=2000`, 65–200 at `+N=20000`, and the `--x-initial-edge` build over seeds
1–100 — all on the pin. `--x-assign` builds a byte-identical binary for this design, so
it is not a separate check.

### A 4-state cross-check

Randomising x shows that the digest does not depend on the value of an uninitialised
bit. It does not show that a 4-state simulator's x-pessimism never reaches the digest:
`x & ~x` is 0 in every 2-state world and x in a 4-state one. A 4-state oracle answers
that. sv2v v0.0.13 (github.com/zachjs/sv2v, BSD-3-Clause) converts the whole design to
Verilog with `-E Always`, and iverilog 13 runs the result after the attribute sv2v leaves
after `always_comb`, `(* full_case, parallel_case *)`, is stripped (`./run.sh sv2v`):

| `+N=` | sv2v + iverilog 13 (4-state) | verilator 5.052 |
|---|---|---|
| 2000 | `32e0e78741376133` | `32e0e78741376133` |
| 20000 | `13b2ddfcd551ba2f` | `13b2ddfcd551ba2f` |

The digest accumulates every cycle through XOR and addition, so one x after reset would
leave x digits in the printed value. The 4-state run prints none. The conversion is a
third program between the source and the simulator, so this check stands beside
verilator; it does not replace it.

Two rows found holes in earlier versions of the digest. The load byte-enable mutation
left the first version unchanged: it never saw a load's byte enables, so the control byte
was added. The late clock gate left the second unchanged: its idle start cycles rotated a
zero digest, so the cycle count was added.
