# 002 · Quickstart

One design carried all the way through: the source, the command, the exact transcript, the VCD
it writes, opening that VCD in a viewer, asking for FST instead, and the echo that records what
the command actually resolved to.

This assumes `vita` is on `PATH` — see [Installation](001_installation.md). Every command below
is run from the repository root, so the paths match the checkout. The design is
[`examples/000_counter.sv`](../../examples/000_counter.sv), shipped in the repository.

---

## 1. The design

A `WIDTH`-parameterized synchronous up-counter with active-high reset, plus a testbench that
drives a free-running clock, pulses reset, prints the count for twelve cycles, dumps a waveform,
and ends with `$finish`.

```systemverilog
`timescale 1ns/1ns

// DUT: increments on every rising clock edge; active-high synchronous reset
// forces the count back to 0.
module counter #(parameter WIDTH = 4) (
    input              clk,
    input              rst,
    output reg [WIDTH-1:0] cnt
);
    always @(posedge clk) begin
        if (rst)
            cnt <= {WIDTH{1'b0}};
        else
            cnt <= cnt + 1'b1;
    end
endmodule

// Testbench: free-running clock, pulse reset, then watch the counter climb.
module tb;
    reg        clk;
    reg        rst;
    wire [3:0] cnt;
    integer    i;

    counter #(.WIDTH(4)) dut (.clk(clk), .rst(rst), .cnt(cnt));

    // 10ns clock period.
    initial clk = 1'b0;
    always #5 clk = ~clk;

    initial begin
        $dumpfile("counter.vcd");
        $dumpvars(0, tb);

        // Hold reset across the first rising edge, then release.
        rst = 1'b1;
        @(posedge clk);          // cnt loads 0 here
        @(negedge clk);
        rst = 1'b0;

        // Count up for 12 cycles, printing the value after each edge.
        for (i = 0; i < 12; i = i + 1) begin
            @(posedge clk);
            #1 $display("t=%0t  cnt=%0d (0x%h)", $time, cnt, cnt);
        end

        $display("done: final cnt=%0d", cnt);
        $finish;
    end
endmodule
```

Three lines carry most of the behaviour:

| Line | Effect |
|---|---|
| `` `timescale 1ns/1ns `` | Sets this file's time unit and precision. A design with no `` `timescale `` anywhere still runs, on a 1ns/1ns base, and adds one warning |
| `$dumpfile` / `$dumpvars` | `$dumpvars` is what opens the waveform file; `$dumpfile` only records the path it will use. Without a `$dumpvars` call no waveform is written at all |
| `$finish` | Ends the run cleanly, which is exit code 0 |

## 2. Run it

One command runs the whole pipeline — preprocess, lex, parse, elaborate, simulate, waveform:

```sh
vita examples/000_counter.sv
```

To split compile, elaborate and simulate into separate invocations, use the staged flow
described in [CLI Reference](004_cli-reference.md).

## 3. The transcript

`$display` output and the closing summary go to stdout:

```text
t=16  cnt=1 (0x1)
t=26  cnt=2 (0x2)
t=36  cnt=3 (0x3)
t=46  cnt=4 (0x4)
t=56  cnt=5 (0x5)
t=66  cnt=6 (0x6)
t=76  cnt=7 (0x7)
t=86  cnt=8 (0x8)
t=96  cnt=9 (0x9)
t=106  cnt=10 (0xa)
t=116  cnt=11 (0xb)
t=126  cnt=12 (0xc)
done: final cnt=12
simulation ended (Finish) at time 126
```

Diagnostics and the counts line go to stderr, so they stay out of the transcript:

```text
errors=0 warnings=0 notes=0
```

Reading it:

- The first rising edge happens while `rst` is high, so `cnt` loads 0 there; the twelve printed
  cycles then run 1 through 12. Each `$display` fires 1 ns after its edge, hence `t=16`, `t=26`,
  and so on.
- `simulation ended (…) at time N` names the reason the run stopped — `Finish`, `Stop`,
  `Quiescent`, `DeltaLimit` or `Error` — and the final time in precision units. This design's
  unit and precision are both 1 ns, so `126` is 126 ns.
- The counts line reports errors (fatals included), warnings, and the informational class.

The exit code says how the run went:

| Code | Meaning |
|---|---|
| `0` | Clean run |
| `1` | Design or runtime error: a lex, parse or elaborate error, a `$fatal`, delta-limit non-convergence, or a warning promoted by `-Werror` |
| `2` | Stale artifact: a `.vu` or `.velab` whose format version, tool major version or schema hash does not match this build, or whose upstream sources have changed. Regenerate it |
| `3` | Usage error: an unknown flag, a missing flag value, no source files, an unreadable input, or an unwritable output |

## 4. The waveform

The file lands at the path `$dumpfile` named, relative to the working directory — here
`counter.vcd` in the repository root. Its header:

```text
$date
   vitamin-sim
$end
$version
   vitamin-sim 0.2.0
$end
$comment
   Generated by vitamin RTL simulator
$end
$timescale 1ns $end
$scope module tb $end
$var reg 1 ! clk $end
$var reg 1 " rst $end
$var wire 4 # cnt [3:0] $end
$var integer 32 $ i [31:0] $end
$scope module dut $end
$var wire 1 % clk $end
$var wire 1 & rst $end
$var reg 4 ' cnt [3:0] $end
$upscope $end
$upscope $end
$enddefinitions $end
```

Then the initial snapshot and the value changes:

```text
$dumpvars
0!
x"
bxxxx #
bxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx $
x%
x&
bxxxx '
$end
#0
1"
0%
1&
#5
1!
1%
b0000 '
b0000 #
```

Points worth knowing about this file:

- `$date` is the literal string `vitamin-sim`, never a clock reading. That is deliberate: two
  runs of the same design produce byte-identical waveform files.
- `$timescale` carries the design's global precision, and every `#N` record is in precision
  ticks.
- Vectors are written at full declared width. Leading `0`, `x` or `z` characters are not
  collapsed, which is a formatting difference from Icarus Verilog, not a value difference.
- `$var` reference names carry the declared bit range (`cnt [3:0]`), and a true scalar has none.

Send the waveform elsewhere without touching the source by passing `-o`, which overrides
`$dumpfile`:

```sh
vita examples/000_counter.sv -o build/counter.vcd
```

## 5. Open it

`counter.vcd` is a standard VCD and opens in any conforming viewer:

- [GTKWave](https://gtkwave.sourceforge.net/) — available from most package managers
  (`apt install gtkwave`, `brew install gtkwave`).
- [Surfer](https://surfer-project.org/) — a Rust waveform viewer.

```sh
gtkwave counter.vcd
# or
surfer counter.vcd
```

Add `clk`, `rst` and `cnt` to the view: `cnt` steps up once per rising `clk` edge and holds at 0
across the reset pulse. vitamin ships no GUI of its own.

## 6. FST instead of VCD

The waveform format follows the output path's extension, compared case-insensitively: a path
ending in `.fst` writes FST, and anything else writes VCD. The rule applies to a `-o` value and
to a `$dumpfile` argument alike.

```sh
vita examples/000_counter.sv -o counter.fst
```

FST is produced by writing a sidecar VCD during the run and transcoding it when the run
finalizes; the sidecar, `counter.fst.vcdtmp`, is deleted on success. If the transcode fails, the
sidecar is kept and a warning names the failure, so no waveform data is lost. The FST carries
the same value-change stream as the VCD by construction, including everything `$dumpoff`,
`$dumpon`, `$dumpall` and `$dumplimit` put into it.

An FST target also pins the waveform writer to a single thread regardless of `--threads`, so the
sidecar is closed before the transcode reads it.

## 7. What actually ran

Once the command lives in a Makefile, the macro values and file lists behind `$(WIDTH)` and
`$(SEED)` stop being visible to whoever reads the log. `-v` prints the resolved invocation as
the first thing in the transcript:

```console
$ vita -v examples/000_counter.sv

invocation: vita -v examples/000_counter.sv
cwd:        /home/you/vitamin-rtl-simulator
sources:    examples/000_counter.sv
threads:    8 (auto)

t=16  cnt=1 (0x1)
...
```

The block is set off by a blank line above and below. A row with nothing in it is omitted
entirely, so a plain invocation prints four rows and a filelist-driven one prints many more:
`filelists:`, `incdirs:`, `defines:`, `plusargs:`, `params:`, `tops:`, `output:`, `obs-dir:`,
`probes:`, `timeout:`, `log:` and `env:` each appear only when they have content. The
`threads:` row names where its value came from — `--threads`, the `VITA_THREADS` environment
variable, or `auto`.

These lines are ordinary progress output, so `-l/--log` captures them in the same stream and
order as the diagnostics and the `$display` transcript. That makes one file a complete record of
the run:

```sh
vita -f build.f -o counter.vcd +SEED=7 -v -l sim.log
```
