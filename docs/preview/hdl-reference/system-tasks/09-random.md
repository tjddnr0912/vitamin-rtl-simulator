# 09 · Random Functions

## Overview

SystemVerilog offers two generations of random-number interface.
The `$random` / `$dist_*` family descends from the Verilog-1995 PLI, and the
`$urandom` / `$urandom_range` family is defined by IEEE 1800-2017 §18.
The two generations differ in signedness (signed vs unsigned), in the scope of the RNG state
(global vs thread-local) and in how they treat a seed, so mixing them takes care.

## vita support

This note describes the language, not the simulator. What vita accepts today is recorded in
[docs/manual/003_language-reference.md](../../../manual/003_language-reference.md).

### `$random` — a global RNG, 32-bit signed

- **Signature**: `$random [(seed)]`
- **Standard**: IEEE 1364-2005 §17.9 (inherited by SV)
- **Returns**: a 32-bit signed integer (negative values included)
- **seed**: optional. It must be a reg, integer or time variable.

```sv
integer r;

r = $random;          // called without a seed — uses the simulator's global RNG
r = $random(42);      // re-initialises the RNG state to seed 42 and returns the first value

// negative values are possible, so a positive range needs an absolute value
r = $random % 100;    // the range -99 to 99 (negatives included!)
r = {$random} % 100;  // reinterpreted as 32-bit unsigned, then mod → 0 to 99 (positive only)
```

**Careful — the RNG state is global**: `$random` shares one RNG across the whole simulation.
In a multi-threaded testbench, which thread calls `$random` changes the values every other thread
receives. Change the order in which threads are created or scheduled and the entire random sequence
changes with it, which makes a run hard to reproduce.

This is the problem `$urandom` was introduced to solve in IEEE 1800.
New code should prefer the `$urandom` family wherever it can.

---

### `$urandom` — a thread-local RNG, 32-bit unsigned

- **Signature**: `$urandom [(seed)]`
- **Standard**: IEEE 1800-2017 §18
- **Returns**: a 32-bit unsigned integer (never negative)
- **seed**: optional. Supplying one re-seeds this thread's RNG.

```sv
logic [31:0] u;

u = $urandom;         // draws from the current thread's RNG
u = $urandom(99);     // re-seeds this thread's RNG with 99
```

**The thread-local RNG model**: IEEE 1800-2017 requires every process — an `initial` or `always`
block, each thread inside a `fork` block, a task/function call chain — to hold an **independent RNG
instance**.

When a new dynamic thread is created (`fork ... join_none` and the like), its initial seed comes
from the next value generated by the parent thread's RNG.
This is called **hierarchical seeding**.
Fix the one top-level seed and the random sequence of the entire hierarchy is fixed with it.

```sv
// fixing the whole seed from the command line
// Synopsys VCS:      +ntb_random_seed=42
// Mentor QuestaSim:  -sv_seed 42
```

**The RNG algorithm, and a cross-simulator caveat**: IEEE 1800-2017 leaves the specific algorithm
behind `$urandom` implementation defined. Tools may use different algorithms, so VCS and QuestaSim
can produce different sequences from the same seed.
The statistical properties of the sequence (an unbiased uniform distribution) are guaranteed; the
specific values are not.

### `$urandom_range` — a uniform draw over a range

- **Signature**: `$urandom_range(max [, min = 0])`
- **Standard**: IEEE 1800-2017 §18
- **Returns**: an unsigned integer in `[min, max]`, both bounds inclusive

```sv
int unsigned v;

v = $urandom_range(7);       // 0 to 7 (min omitted → 0)
v = $urandom_range(9, 1);    // 1 to 9
v = $urandom_range(15, 8);   // 8 to 15

// with max < min the behaviour is implementation defined — mind the argument order
// ($urandom_range(3, 10) may differ between tools)
```

`$urandom_range` draws from the same thread-local RNG as `$urandom`.

### The `$dist_*` family — distribution draws

The `$dist_*` functions are PLI functions rooted in IEEE 1364-2005 §17.9.
IEEE 1800-2017 Annex N carries the C source of the algorithms, so a standard-conforming simulator
produces **the same sequence for the same seed across tools**.
(Unlike `$urandom`, cross-simulator reproducibility is guaranteed.)

**The seed parameter is inout**: every `$dist_*` function treats its seed as an inout.
Each call updates the seed internally, and the updated value becomes the input seed of the next
call. The seed variable must be of type **integer**.

```sv
integer seed = 12345;  // the starting seed — the integer type is required
integer r;

r = $dist_uniform(seed, 0, 100);   // a uniform integer in 0..100; seed is updated
r = $dist_uniform(seed, 0, 100);   // a different value (the seed has already moved)
```

---

#### `$dist_uniform`

- **Signature**: `$dist_uniform(seed, start, end)` → integer
- **Meaning**: a uniformly distributed integer over `[start, end]`, with start ≤ result ≤ end.
- **Note**: `$random` can be implemented internally as a special case of `$dist_uniform`.

```sv
integer seed = 1;
integer r;

r = $dist_uniform(seed, 1, 6);    // a die roll (1 to 6)
r = $dist_uniform(seed, -10, 10); // a negative range works too
```

---

#### `$dist_normal`

- **Signature**: `$dist_normal(seed, mean, std_deviation)` → integer
- **Meaning**: an integer from the normal (Gaussian) distribution with mean `mean` and standard
  deviation `std_deviation`.
- **Careful**: the return is an integer, so the tails of the distribution are truncated.
  This function is not the right tool where real precision matters.

```sv
integer seed = 777;
integer r;

r = $dist_normal(seed, 100, 15);  // an integer with mean 100 and standard deviation 15
```

---

#### `$dist_exponential`

- **Signature**: `$dist_exponential(seed, mean)` → integer
- **Meaning**: an integer from the exponential distribution with mean `mean`.
  Used to model inter-arrival times in communication and queueing simulations.

```sv
integer seed = 3;
integer r;

r = $dist_exponential(seed, 10);  // an exponential distribution with mean 10
```

---

#### `$dist_poisson`

- **Signature**: `$dist_poisson(seed, mean)` → integer
- **Meaning**: an integer from the Poisson distribution with mean `mean`.
  Used to model the number of events per unit time.

```sv
integer seed = 55;
integer r;

r = $dist_poisson(seed, 5);  // a mean of 5 occurrences
```

---

#### `$dist_chi_square`

- **Signature**: `$dist_chi_square(seed, degree_of_freedom)` → integer
- **Meaning**: the chi-square (χ²) distribution with `k` degrees of freedom,
  that is the distribution of the sum of the squares of `k` standard normal variates.

---

#### `$dist_t`

- **Signature**: `$dist_t(seed, degree_of_freedom)` → integer
- **Meaning**: Student's t-distribution with `k` degrees of freedom.
  Used in small-sample statistical modelling.

---

#### `$dist_erlang`

- **Signature**: `$dist_erlang(seed, k_stage, mean)` → integer
- **Meaning**: the k-stage Erlang distribution. Used to model the waiting time through k stages of
  a service queue. With `k=1` it is the exponential distribution.

---

## $random vs $urandom at a glance

| Aspect | `$random` | `$urandom` |
|------|----------|-----------|
| Return type | 32-bit signed | 32-bit unsigned |
| Scope of the RNG state | global | thread-local |
| Standard | IEEE 1364-2005 §17.9 | IEEE 1800-2017 §18 |
| Multi-thread reproducibility | fragile | robust (hierarchical seeding) |
| Cross-simulator reproducibility | implementation defined | implementation defined |
| seed argument | optional, reg/int/time | optional |

## Synthesizability

❌ None of these functions is synthesizable — they are simulation-only.
Where RTL itself must generate random values, build the generator as a circuit (an LFSR, say).
