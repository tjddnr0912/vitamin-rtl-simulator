# 07 · Waveform output — VCD and FST

This is the waveform emission contract: what makes vita open a dump file, the exact bytes it writes,
the naming rules for scopes and variables, the dump-control system tasks, the FST dispatch, and the
determinism guarantee that gates all of it. The serializer lives in `crates/vcd-writer`; the driver
that decides when to call it lives in `crates/sim-engine`.

---

## 1. RTL-driven: what opens a file

The writer is passive. It never decides to dump; the dump system-task handlers drive it.

| Rule | Consequence |
|---|---|
| `$dumpvars` is the only call that creates a file | A run with no `$dumpvars` writes no waveform |
| `$dumpfile(name)` only records a pending path | `$dumpfile` alone creates nothing |
| `-o <path>` alone, with no `$dumpvars` in the RTL, creates nothing | The CLI overrides the path, it does not start a dump |
| `$dumpon` / `$dumpoff` / `$dumpall` / `$dumpflush` before any `$dumpvars` are no-ops | There is no writer to drive yet |

The dump path is resolved at the first `$dumpvars`, in this order:

1. the CLI `-o` / `--out` override,
2. the `$dumpfile` argument,
3. the literal `dump.vcd`.

`$dumpfile` accepts a non-constant argument and renders its value in decimal as the filename; this
is not an error.

The second and every later `$dumpvars` warns once with `VITA-W4021` and does nothing: the header is
already written and cannot be rewritten. If `File::create` on the resolved path fails, `VITA-W4018`
is emitted, any FST target is dropped and the simulation continues with no waveform. A final flush
failure is `VITA-W4019`.

### `-o` per applet

| Applet | `-o` meaning |
|---|---|
| `vita` (one-shot) | waveform output path; overrides `$dumpfile` |
| `vrun` | waveform output path, same semantics; rejected when it names the input `.velab` |
| `vcmp` | `.vu` output path, not a waveform |
| `velab` | `.velab` output path, not a waveform |

Both spellings are accepted. A missing value is `error[VITA-E0001]: '-o' needs an argument` with
exit `EXIT_CLI_ERROR`; a repeated `-o` records an override note and the last one wins. `-o` is on
the filelist `takes_value` list, so an `-o` inside a `-f` / `-F` filelist is not path-rewritten.

## 2. VCD header

`write_preamble(date, unit)` emits exactly this, in this order, with three-space indentation inside
the `$date`, `$version` and `$comment` blocks and `$timescale` on one line:

```vcd
$date
   vitamin-sim
$end
$version
   vitamin-sim 0.2.0
$end
$comment
   Generated by vitamin RTL simulator
$end
$timescale 1ns $end
```

The `$date` text is taken verbatim from `SimOpts::vcd_date`, whose default is the fixed string
`vitamin-sim`. No CLI path overrides it, so a vita VCD never contains a wall-clock read. That is the
determinism guarantee (§9). `$version` carries the crate version, `0.2.0`.

### `$timescale` and time records

The `$timescale` value is the design's **global precision**, not its time unit. The CLI computes it
with `timescale_unit_string(global_prec_exp)`: the exponent is clamped to `[-15, 2]`, floored to a
multiple of three, and rendered as a magnitude in `1|10|100` followed by a unit in
`s|ms|us|ns|ps|fs`. With no `` `timescale `` directive anywhere the default is `1ns`. See
[08 · timescale and timing](08-timescale-and-timing.md) for how the global precision is derived.

Time records are `#<t>` with `t` a decimal `u64` **in global-precision ticks**. Under
`` `timescale 10ps/1ps `` the header reads `$timescale 1ps $end` and a `#1` delay produces the
record `#10`.

`set_time` dedups: repeating the current timestamp emits nothing, so `#t` appears at most once per
timestamp. The driver calls `set_time(now)` unconditionally right after the `$dumpvars` block, so a
`#0` record follows the initial block even when nothing changed.

## 3. Scope tree

### 3.1 Scope kinds

The writer's `ScopeType` has five variants — `Module`, `Task`, `Function`, `Begin`, `Fork` —
rendered as the IEEE 1364 §18 keywords `module`, `task`, `function`, `begin`, `fork`.

| Status at HEAD | |
|---|---|
| The engine emits `ScopeType::Module` and nothing else | `task`, `function`, `begin` and `fork` never appear in a vita waveform; every scope line reads `$scope module <name> $end` |

### 3.2 Naming per source construct

Scope segments come from each net's fully-qualified dotted name: everything but the last segment is
the scope path, the last segment is the `$var` reference leaf.

| Source construct | Scope segment emitted |
|---|---|
| module instance | `<inst_name>` |
| interface instance | `<inst_name>` — declared as `module`, not `interface` |
| named generate-for block | `<label>[<genvar value>]`, e.g. `LOOP[0]`, `LOOP[1]`. The index is the genvar VALUE, not a zero-based counter |
| unnamed generate-for block | `genblk<N>[<genvar value>]`, N being the construct's one-based number in its scope (IEEE 1800 §27.6) |
| unnamed generate-if / generate-case arm | `genblk<N>[0]` — the waveform carries the raw hierarchical key including the `[0]` |
| function | `$func$<name>` |
| static task | `$itask$<task>$L`, holding the task's static locals |
| block-local requiring its own storage | `$blk$<n>` |
| named `begin : LBL` inside a process | none — the local is flattened into the enclosing module scope under its bare leaf name |
| `fork ... join` arm (`begin : ARM`) | none — same flattening |
| package | none — package nets are excluded entirely (§4.2) |
| class | none — class objects live on the class heap, not in the net table, and have no `$var` |

### 3.3 Ordering and empty scopes

The tree is a sorted-leaf walk over the net table:

1. start with net-table order;
2. drop every net whose hierarchical name starts with `$pkg$`, before the walk, so no empty package
   scope is emitted;
3. drop every net whose LEAF starts with `$ia_tmp$` — intra-assignment-delay captures and discarded
   system-call sinks. A name containing a backslash is an escaped identifier and is always kept,
   because the leaf split cannot be trusted on it;
4. stable-sort on the scope-prefix segment slice. The comparison is lexicographic **byte** order over
   the segments, so within one scope the variables keep net-table order;
5. walk the sorted leaves, popping to the common prefix and pushing the remainder.

Byte order puts top-level nets first — the empty scope path sorts first — then the sub-scopes in
byte order of their segments (`$` 0x24 < uppercase < lowercase).

**Empty scopes are emitted.** The scope push happens before the per-net exclusion tests, so a scope
whose every net is filtered out still produces a `$scope`/`$upscope` pair:

```vcd
$scope module top $end
$var wire 1 ! tz $end
$scope module u_mid $end
$scope module u_leaf $end
$upscope $end
$upscope $end
$upscope $end
```

At the end of the walk every remaining scope is popped and `$enddefinitions $end` closes the header.

## 4. `$var` declarations

### 4.1 Dumpable types

`vcd_var_type` maps `sim_ir::NetKind` onto the `$var` type keyword:

| `NetKind` | `$var` type | Declared? |
|---|---|---|
| `Wire` | `wire` | yes |
| `Logic` | `wire` | yes — a `logic` net dumps as `wire` |
| `Reg` | `reg` | yes |
| `Integer` | `integer` | yes |
| `Real` (`realtime` maps to the same variant) | `real` | yes |
| `DynArray` | — | no |
| `Queue` | — | no |
| `Assoc` | — | no |
| `AssocStr` | — | no |
| `String` | — | no |

The five handle kinds have no `$var` form, because a variable-length value has no fixed width. They
are skipped before `declare_var` on both the hierarchical and the flat path.

| Status at HEAD | |
|---|---|
| The variable-length exclusion is silent | A `string s;` or `int dq[$];` produces no `$var`, no change record and no diagnostic |
| The writer's `VarType` has 18 variants (`event`, `integer`, `parameter`, `real`, `realtime`, `reg`, `supply0`, `supply1`, `time`, `tri`, `triand`, `trior`, `trireg`, `tri0`, `tri1`, `wand`, `wire`, `wor`) | Only `wire`, `reg`, `integer` and `real` are reachable from the engine. No `NetKind` maps to `parameter`, so vita emits no parameter block |

### 4.2 Other exclusions

| Excluded | Loud? |
|---|---|
| package variables (`$pkg$…` prefix) | Silent for a bare dump. An explicit `$dumpvars(…, pkg_var)` selection warns once with `VITA-W4026`, and the net is still excluded |
| `$ia_tmp$…` synthetic temporaries | silent |
| frame-local nets — call-frame arena residents, i.e. `automatic` subroutine locals | silent |
| variable-length handles (§4.1) | silent |
| nets outside the `$dumpvars` filter | silent, by design |

### 4.3 Line format

```vcd
$var {type} {width} {idcode} {reference} $end
```

`{width}` is the net's width clamped to a minimum of 1, so a zero-width net is declared as width 1.
`{reference}` may itself contain a space and a bracketed range, which makes the emitted line five
tokens before `$end`, for example `$var reg 8 ) mem[4] [7:0] $end`.

### 4.4 The declared bit-range rule

A bit vector carries its DECLARED `[msb:lsb]` range so that a viewer labels an ascending `[0:3]` or
a non-zero-base `[7:4]` vector correctly instead of defaulting to `[width-1:0]`. IEEE 1364-2005
§18.2.3.2 gives `<reference> ::= id [ [msb:lsb] ]`; iverilog is the oracle. `vcd_var_reference_decl`
decides, given the leaf name (already array-indexed), the width, the stored `msb`/`lsb` and an
optional declared range from the `net_decl_ranges` sidecar:

```
is_vector = width > 1 || msb != 0 || lsb != 0

1. !is_vector, or the type is real/realtime   ->  "{base}"                bare name
2. declared range present and |dm-dl|+1 == w  ->  "{base} [{dm}:{dl}]"    declared range
3. |msb-lsb|+1 == width                       ->  "{base} [{msb}:{lsb}]"  stored range
4. otherwise                                  ->  "{base} [{width-1}:0]"  flat fallback
```

A "vector" here is anything that is neither a true scalar nor `[0:0]`. Rule 4 exists because a
packed multi-dimensional net stores `msb = width-1` with a stale outer-dimension `lsb`, so the span
can disagree with the flat width; emitting that raw range would be internally inconsistent.

| Declaration | `$var` line |
|---|---|
| `logic clk;` | `$var wire 1 ! clk $end` — bare name |
| `logic [0:0] z0;` | `$var wire 1 & z0 $end` — `[0:0]` collapses, iverilog parity |
| `logic [5:5] one;` | `$var wire 1 % one [5:5] $end` — a one-bit net at a non-zero index keeps its range |
| `logic [3:0] cnt;` | `$var wire 4 " cnt [3:0] $end` |
| `logic [0:3] asc;` | `$var wire 4 # asc [0:3] $end` |
| `logic [7:4] hi;` | `$var wire 4 $ hi [7:4] $end` |
| `integer ii;` | `$var integer 32 ' ii [31:0] $end` |
| `real rr;` | `$var real 64 ( rr $end` — width 64, never a range |
| `logic [3:-2] x;` | `$var … x [3:-2] $end` — rule 2 |
| `logic [1:0][3:-2] mp;` | `$var … mp [11:0] $end` — rule 4 |

Negative packed bounds are the reason the declared range is a sidecar at all. `NetVar.msb`/`lsb` are
frozen `u32`, so `logic [3:-2] x` is stored normalized as `[5:0]`. The bits are the same, but a
viewer would then label every bit with the wrong index, so the declared bound rides the
`net_decl_ranges` sidecar and rule 2 restores it. The sidecar is empty for every net with
non-negative bounds, so ordinary designs are byte-identical either way.

### 4.5 Arrays: one `$var` per element

A net with `array_len > 1` declares `array_len` separate `$var` lines, one per element, each of the
net's width. Element names come from `elem_name`: the row-major word index is decomposed into
per-dimension digits and each digit is offset by that dimension's declared low bound, taken from the
`net_dims` sidecar of `(lo, size)` pairs. A net absent from the sidecar is treated as one-dimensional
and zero-based.

| Declaration | Element references |
|---|---|
| `reg [7:0] m [4:7];` | `m[4] [7:0]`, `m[5] [7:0]`, `m[6] [7:0]`, `m[7] [7:0]` |
| `reg [3:0] g [0:1][2:3];` | `g[0][2]`, `g[0][3]`, `g[1][2]`, `g[1][3]` |
| `int a[-1:1];` | `a[-1]`, `a[0]`, `a[1]` — exactly three variables |

iverilog does not dump memories at all (`cannot dump a vpiMemory`), so the per-element naming is
pinned by hand to the de-facto bracketed convention rather than to an oracle.

### 4.6 Identifier codes

An `IdCode` is a `u32` ordinal rendered as bijective base-94 over the printable ASCII range
`!` (33) through `~` (126). `IdCode::FIRST` is ordinal 0, which renders as `!`, and each
`declare_var` takes the next ordinal.

| Ordinal | Rendering |
|---|---|
| 0 | `!` |
| 1 | `"` |
| 93 | `~` |
| 94 | `!!` |
| 95 | `!"` |

IEEE 1364 §18 does not fix an encoding algorithm; it requires only one or more characters from
printable ASCII 33–126. The identifier space here is `2^32` codes. A variable keeps its code for the
whole file: the writer holds `vars: Vec<VarMeta>` in declaration order plus a `by_id` index. Array
elements each get their own code; the engine-side tables are `NetSlot.vcd_id` for a scalar and
`NetSlot.vcd_word_ids` for an array.

## 5. Value-change encoding

### 5.1 Bit mapping

Bits come from a `BitPacked` `(val, unk)` pair, word 0 bit 0 being the LSB. The characters are
always lowercase:

| `(val, unk)` | Character |
|---|---|
| `(0, 0)` | `0` |
| `(1, 0)` | `1` |
| `(0, 1)` | `x` |
| `(1, 1)` | `z` |

### 5.2 Record forms

| Value kind | Bytes | Examples |
|---|---|---|
| scalar, `width <= 1` | `<char><id>\n` — **no space** | `1!`, `x"`, `z#` |
| vector, `width > 1` | `b<MSB..LSB> <id>\n` — space before the id | `b0101 !`, `bzx !` |
| real / realtime | `r<value> <id>\n` — no space after `r`, space before the id | `r0`, `r0.1`, `r-2.5` |

Uppercase `B` and `R` are legal in the format and are accepted on the read side; vita always writes
lowercase.

Vectors are always written at FULL WIDTH. IEEE 1364 permits collapsing leading `0`/`x`/`z`, and
iverilog does collapse; vita deliberately does not, because full width makes the golden output
trivially predictable and a reader expands the collapsed form identically anyway. A multi-word
vector reads bits `width-1 .. 0` out of the packed words, so an 80-bit value renders 80 characters.

The real value is `f64::from_bits(bits.val[0])` — vita stores reals as raw bits — formatted by
`fmt_g(x, 16)`, vita's own deterministic C `%g`, shared with `$display %g`. Non-finite values are
`nan`, `inf` and `-inf` in lowercase, matching C and iverilog; `-0.0` renders as `0`. Exponent form
is used when `exp < -4 || exp >= p`, with an exponent of at least two digits (`1e-05`, `6.022e+23`).

There is no array-aggregate record: each element change emits an ordinary scalar or vector record
under that element's own identifier. Strings, queues, associative and dynamic arrays have no
encoding at all, because they are never declared.

### 5.3 When a record is written

`emit_vcd_change` / `emit_vcd_packed` are gated on the engine's `dumping` flag. Each calls
`set_time(now)` and then `value_change`; `set_time` dedups, so the `#t` line is written at most once
per timestamp. The identifier lookup (`vcd_id_for`) is shared with the native backend, so both
backends write the same bytes for the same value stream.

## 6. The `$dumpvars` initial block

```vcd
$dumpvars
<one change record per declared variable, no #time prefix>
$end
```

- The values come from a full snapshot that walks the net table in **net-index order**. That is a
  different order from the `$var` declaration order, which is scope-sorted, so the identifiers in
  the block body are not in ascending order.
- An uninitialized four-state net snapshots as all-`x`, a two-state net (`int`) as `0`, a `real` as
  `r0`.
- The block is not limit-checked: `dump_initial` writes records directly. The `$dumplimit` budget
  guards `value_change`, `set_time`, `dump_all`, `dump_off` and `dump_on` only.
- `set_time(now)` follows the block immediately, so a `#<now>` record always comes next.

## 7. Dump-control system tasks

All seven tasks are implemented, and all of them work identically on the FST path (§8).

| Task | Behaviour |
|---|---|
| `$dumpfile(name)` | Stores the pending path; creates nothing. Consulted only at the first `$dumpvars`; a later call has no effect. A non-constant argument is rendered in decimal. |
| `$dumpvars(...)` | Opens the file, builds the filter (§7.1), writes the preamble, the scope tree, the `$var` lines and `$enddefinitions`, then the initial block, then `set_time(now)`, then enables dumping. The first call wins; later calls warn `VITA-W4021` once and no-op. |
| `$dumpoff` | `set_time(now)`, then `$dumpoff`, then for EVERY declared variable regardless of kind `x<id>` when `width <= 1` and `b<x…x> <id>` with `width` x characters otherwise, then `$end`. Disables dumping. A `real` therefore gets a 64-character x vector here, not `rx`. |
| `$dumpon` | Enables dumping, snapshots every declared variable, then `set_time(now)`, `$dumpon`, the records, `$end`. Records use the normal encoder, so a `real` re-emits as `r…`. |
| `$dumpall` | Identical to `$dumpon` except that it does not turn dumping back on: a checkpoint, not a resume. |
| `$dumpflush` | Pushes the 64 KiB buffered writer to the OS. Errors are swallowed here and surface at finalize as `VITA-W4019`. |
| `$dumplimit(bytes)` | Evaluates argument 0 to a `u64`. A size of 0, an X/Z value, or a missing argument is a no-op with no budget installed. Otherwise the byte budget is installed. |

`$dumplimit` mechanics: the sink is wrapped in a byte-counting adapter; the check fires when
`bytes_written >= limit`, emits the single line `$comment Dump limit reached $end` exactly once,
latches, and drops every subsequent guarded record — including `#t` time records.

A `$comment` block may appear anywhere, in the header or in the simulation-data section.

### 7.1 `$dumpvars` level and scope arguments

The arguments are a real filter over the net set, not a drop. Each argument is classified by its
elaborated expression:

| Argument shape | Treated as |
|---|---|
| a signal reference | a NET target — that net is selected. A whole-array argument selects every element |
| a UTF-8 string constant | a SCOPE argument. Elaborate encodes it as `"{fq}\u{0001}{raw}"`, a two-candidate list: the elaborate-scope-resolved hierarchical path first, then the raw text as a root-absolute path |
| any other constant | the LEVEL, if no level has been seen yet |
| anything else | ignored |

Resolution:

- With no net targets and no scope arguments the filter is absent and the whole design is dumped. A
  bare `$dumpvars` and a level-only `$dumpvars(0)` both dump everything.
- The level defaults to 0.
- For each scope argument, the first candidate that prefixes some net name as `"{cand}."` wins. Every
  net whose name starts with `"{scope}."` is then selected when the level is 0, or when
  `depth(name) - depth(scope) <= level`, where `depth` counts dot-separated segments. So
  `$dumpvars(1, top)` selects top's OWN variables only, iverilog-pinned, and `$dumpvars(0, top)`
  selects the whole subtree.
- If every scope argument fails to resolve and no net arguments were selected, the filter degrades to
  dump-everything rather than producing an empty waveform.
- Explicitly selecting a package net warns once with `VITA-W4026`, and the net stays excluded.

## 8. FST output

FST (Fast Signal Trace) is the GTKWave native format, also read by Surfer. It is driven through the
same system tasks as VCD; only the file extension differs.

```systemverilog
module tb;
  reg clk; reg [3:0] cnt; real r;
  initial begin
    $dumpfile("wave.fst");   // .fst extension -> FST; anything else -> VCD
    $dumpvars(0, tb);        // identical to the VCD path
    // ... stimulus ...
    $finish;
  end
endmodule
```

### 8.1 Dispatch

The target format is decided by `path.to_ascii_lowercase().ends_with(".fst")` on the **resolved**
path, so `-o` wins over `$dumpfile`. The test is case-insensitive: `.fst` and `.FST` both select
FST. Any other extension, or none, writes a plain VCD. `vita design.sv -o wave.fst` and
`vrun design.velab -o wave.fst` therefore produce FST regardless of the `$dumpfile` argument in the
source.

### 8.2 The transcode

There is no native FST sink. The engine always writes a VCD; the FST is a post-pass.

1. `$dumpvars` writes the VCD to a sidecar at `<path>.fst.vcdtmp` and records the FST target.
2. An FST target forces the VCD sink single-threaded even under `--threads` 2 or more, so the file is
   fully flushed and closed with no writer thread to join before the transcode runs.
3. At the end of `simulate` the writer is dropped, which flushes and closes the sidecar, and
   `vcd_writer::fst::transcode_vcd_to_fst(tmp, fst_path, version, date)` runs.
4. On success the sidecar is deleted. On failure `VITA-W4019` is emitted with the message
   `FST transcode failed for '<path>': <err>` and the sidecar VCD is deliberately KEPT, so the
   verified waveform survives for debugging.

Because the transcode replays the value-change stream, FST is equivalent to VCD by construction:
every dump semantic — `$dumpoff` writing all-x, `$dumpon`, `$dumpall`, `$dumplimit` — is already
baked into the VCD stream and carries over for free. No separate binary sink is wired into the
value-change path, so there is no branch where the two formats can disagree.

### 8.3 Encoder

The compressed geometry, hierarchy and value-change blocks are produced by the pure-Rust
`fst-writer` crate, pinned exactly at `=0.3.1` (BSD-3-Clause; `lz4_flex` + `miniz_oxide`). vita never
touches the binary encoding itself.

| Fact | Value |
|---|---|
| `fst-writer` | `=0.3.1`, pinned exactly |
| Independent reader used as the transcode oracle | dev-dependency `fst-reader = "=0.10.2"` |
| Workspace MSRV | 1.85 — `fst-writer` 0.3.x is edition 2024. vita's own crates stay edition 2021 |

The 0.2.x line writes a malformed FST time table that GTKWave and `fst-reader` tolerate but wellen,
the reader behind Surfer, rejects with `I/O operation failed`; 0.3.x fixes it. The pin is the reason
the workspace MSRV floor is 1.85, and 0.3.1 is verified to load in Surfer 0.7.0.

### 8.4 What the FST path uses

| FST field | Value |
|---|---|
| `FstInfo.start_time` | always 0 |
| `FstInfo.timescale_exponent` | derived from the VCD `$timescale` (table below) |
| `FstInfo.version` | `vitamin-sim {CARGO_PKG_VERSION}` |
| `FstInfo.date` | the VCD date string, `vitamin-sim` |
| `FstInfo.file_type` | `Verilog` |
| hierarchy | `scope(name, "", ty)` / `up_scope()` / `var(name, sig_ty, ty, Implicit, alias)` |
| signal type | `real()` for `real`/`realtime`, otherwise `bit_vec(width)` |
| variable direction | always `Implicit` |
| aliases | a repeated VCD identifier maps to the same signal handle, so a net dumped under several names is one signal |
| body | `time_change(t)` and `signal_change(handle, bytes)` only |

Not used: enum tables, attributes, blackout records, per-scope component strings (always empty),
explicit variable directions, source-line attributes.

Mapping details:

- Scope keywords map `task`→`Task`, `function`→`Function`, `fork`→`Fork`, `begin`→`Begin`,
  `generate`→`Generate`, `struct`→`Struct`, `union`→`Union`, `class`→`Class`,
  `interface`→`Interface`, `package`→`Package`, `program`→`Program`, anything else →`Module`. In
  practice only `module` ever arrives, because the engine writes only `module` (§3.1).
- The 18 VCD variable keywords map onto the matching FST variable type; an unknown keyword becomes
  `Wire`.
- `timescale_exponent` splits the leading digits off the unit: the magnitude contributes
  `1`→0, `10`→1, `100`→2, anything else→0, and the unit contributes `s`→0, `ms`→-3, `us`→-6,
  `ns`→-9, `ps`→-12, `fs`→-15, anything else→-9. The result is the sum.

  | `$timescale` | FST exponent |
  |---|---|
  | `1ns` | -9 |
  | `10ns` | -8 |
  | `100ps` | -10 |
  | `1fs` | -15 |
  | `1s` | 0 |

- **Name folding**: the `$var` reference range is concatenated into the FST variable NAME with no
  separator, so `$var reg 4 " cnt [3:0] $end` becomes the FST variable `cnt[3:0]`. This is the
  GTKWave convention.
- **Vector extension**: a short VCD vector is left-padded to the declared width per IEEE 1364
  §18.2.1 (`x` extends with `x`, `z` with `z`, otherwise `0`), and `X`/`Z` are lowercased on every
  branch. vita's own writer always emits full-width lowercase, so this matters only for foreign VCDs.
- **Real unknown**: an `r<float>` record becomes `f64::to_le_bytes`. A bit-vector record landing on a
  real signal — which is exactly what `$dumpoff` produces — maps to `f64::NAN`, the real-domain
  unknown, matching iverilog's `rNaN`. Feeding x bytes to a real signal change would reinterpret
  them as a garbage float, which is a silent-wrong.
- **Records understood**: `#<t>`; `b`/`B` vector plus the next token as the identifier; `r`/`R` real
  plus the next token; `0`/`1`/`x`/`X`/`z`/`Z` scalar, where value and identifier are one token;
  `$comment`, skipped to `$end`. `$dumpvars`, `$dumpoff`, `$dumpon`, `$dumpall` and `$end` are
  no-ops, because their inner value lines are handled by the arms above. Unknown records are ignored.

### 8.5 Known FST limitation

An unresolved upstream `fst-writer` defect in the time-table LZ4 encoding
([issue #4](https://github.com/ekiwi/fst-writer/issues/4), present in both 0.2.x and 0.3.x) makes
wellen and Surfer reject an FST whose value-change time count is exactly 11, with
`I/O operation failed`. It reproduces with raw `fst-writer` alone and is independent of vita. This is
a loud refusal, never a silent-wrong: an FST that loads always carries correct values. A sweep of
time counts from 1 to 1000 fails only at 11, so large dumps — the reason FST exists — are safe, and a
small testbench is better served by VCD.

| Status at HEAD | |
|---|---|
| The limitation is not represented in source | No code comment, guard or test references it; it is a documented property of the pinned dependency, not a vita behaviour |

### 8.6 FST non-goals

- **Native FST streaming**, writing value changes straight to FST with no VCD sidecar. The transcode
  is the correct-or-loud choice; removing the sidecar I/O is an optimization, not a correctness
  requirement.
- **LXT / LXT2**, the legacy GTKWave formats.

## 9. Byte determinism

### 9.1 What makes the bytes deterministic

| Source of variance | How it is removed |
|---|---|
| `$date` wall clock | The date is the fixed string `vitamin-sim`; no clock is ever read |
| `$version` | The crate version, fixed per build |
| identifier allocation | sequential in declaration order |
| variable order | deterministic byte-order sort on the scope path, stable within a scope |
| snapshot order | net-index order |
| vector formatting | always full width, never a locale-dependent path |
| real formatting | vita's own `fmt_g`, built only from Rust `{:e}` and `{:.*}`, never a libm transcendental; identical on every supported platform |
| thread count | the writer thread receives the exact pre-serialized byte stream; `--threads` is wall-clock only |
| backend | the identifier tables are shared simulation-state metadata; only values cross the interpreter/native seam |

### 9.2 The gates that enforce it

| Gate | What it pins |
|---|---|
| `golden_vcd` (`crates/vcd-writer/src/lib.rs`) | The whole file byte for byte, header to last record, with the version substituted; also the trailing newline |
| `value_change_byte_exact_scalar_and_vector` | `#0\n1!\nb0101 "\n` |
| `real_var_emits_r_format` | a `real` must not emit a binary vector |
| `fmt_g_determinism_golden` | 16 cases at precision 6 and 16, including `inf`, `-inf`, `nan`, `-0.0` |
| `$dumpoff` / `$dumpon` writer tests | the exact block text, and that suppressed changes do not appear |
| `$dumpall` writer test | `#5\n$dumpall\n1!\nb0011 "\n$end\n` |
| `$dumplimit` writer test | the comment is inserted once and later records — including `#0` — are suppressed |
| `idcode_sequence` | `!`, `"`, `~`, `!!` |
| `crates/sim-engine/tests/backend_equiv.rs` | the interpreter and the VM produce identical VCD bytes; `gate_actually_compares_vcd_bytes` proves the gate has teeth |
| `crates/sim-engine/src/native/run_tests.rs` | the VM and the native backend produce identical VCD bytes, on per-design VCD targets, after asserting the native run really was native |
| `threads_vcd_byte_identical` (`crates/sim-engine/tests/threads.rs`) | `--threads 1` and `--threads 4` produce identical bytes on a dump-heavy design |
| `crates/cli/tests/staged_flow.rs` | `vcmp → velab → vrun` is byte-equal to `vita -o`, including a timescaled design |
| `crates/cli/tests/worklib.rs` | byte-identical across worklib pipelines |
| `vcd_to_fst_roundtrips` (`crates/vcd-writer/src/fst.rs`) | the FST read back with `fst-reader` has the same effective waveform as the source VCD |
| `crates/cli/tests/fst_waveform.rs` | the `.fst` waveform equals the live iverilog VCD for the same design; the sidecar is cleaned up; a non-`.fst` path still starts with `$date` |
| `crates/cli/tests/vcd_array.rs` | array element naming, declared indices, two-dimensional brackets, the staged dims sidecar, and the four `$dumpvars` filter cases |

| Status at HEAD | |
|---|---|
| FST **byte** determinism is not asserted anywhere | Every FST test asserts read-back waveform equality. `fst-writer`'s internal encoding is outside vita's control |

### 9.3 Recorded formatting differences from iverilog

All three are formatting, not semantics:

- iverilog strips leading zeros from vector values (`b100010`) where vita writes the full width
  (`b00100010`);
- iverilog emits an extra parameter block before `#0`; vita emits none, because `parameter` is an
  unreachable variable type;
- iverilog closes with a bare trailing `#N` time marker that vita does not write.

## 10. Writer API

`vcd-writer` is generic over `std::io::Write`, so tests target an in-memory `Vec<u8>` and production
targets a `File` with no code difference. The public surface:

| Item | Shape |
|---|---|
| `IdCode` | `pub struct IdCode(u32)`; `const FIRST`; `next()`; `ordinal()`; `Display` renders base-94 |
| `ScopeType` | `Module \| Task \| Function \| Begin \| Fork` |
| `VarType` | the 18 IEEE 1364 §18 variants |
| `VcdWriter<W: Write>` | `new(sink)`, `bytes_written()`, `set_limit(u64)`, `is_limit_reached()`, `width_of(IdCode)`, `write_preamble(date, unit)`, `push_scope(ScopeType, name)`, `pop_scope()`, `declare_var(VarType, width, reference) -> io::Result<IdCode>`, `write_header()`, `write_comment(text)`, `value_change(IdCode, &BitPacked, width)`, `set_time(u64)`, `dump_initial(iter)`, `dump_all(iter)`, `dump_off()`, `dump_on(iter)`, `flush()` |
| `VcdWriter<Vec<u8>>::into_string()` | test convenience |
| `fmt_g(x: f64, p: i32) -> String` | the shared deterministic `%g`, also used by `$display %g` |
| `fst::transcode_vcd_to_fst(vcd_path, fst_path, version, date)` | the only public FST entry point |

The caller's pipeline is: preamble, scopes and `$var` declarations, `write_header`, `dump_initial`,
then alternating `set_time` and `value_change`, with `dump_off`/`dump_on`/`dump_all` interleaved, and
`flush` at end of file.

Every record method terminates its line with `\n`, so a well-formed stream ends with a newline by
construction and `flush` appends nothing. This matters: GTKWave overruns its buffer on a file with no
final newline and reports `Unknown VCD identifier`
([GTKWave issue #336](https://github.com/gtkwave/gtkwave/issues/336)).

Internally the sink is wrapped in a byte-counting adapter for `$dumplimit`, and a reusable scratch
buffer builds each change record so the hot path does not allocate. In the engine the sink is a
64 KiB `BufWriter`, optionally in front of a writer thread with a bounded FIFO of 8 chunks.

## 12. Non-goals

- **Extended VCD (`$dumpports*`)** — the commercial port-strength extension. Out of scope.
