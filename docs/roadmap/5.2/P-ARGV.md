* symptom: a command-line argument that is not UTF-8 panics before any design runs: `cli/src/pipeline.rs:26` `std::env::args()` exits 101 on `+S=\xC8A` (PRE 9d60771d) where iverilog 13.0 and verilator 5.052 read the plusarg and print `c8 41`
* cause: the plusarg store is `String` (the `$test$plusargs` / `$value$plusargs` queries compare bytes since Q-STRBYTES (§4.5.629): `sim-engine/src/eval/sysfunc.rs:555`, `sim-engine/src/exec/plusargs.rs:67` / `:76`)
* a `$value$plusargs` numeric conversion reads a lossy view of the argv bytes after the prefix (Q-STRBYTES boundary B19, `sim-engine/src/exec/plusargs.rs:80`): with argv `+S=\xC3\xA9`, `$value$plusargs("S=\303%d", v)` hits on the byte prefix and writes x as iverilog 13.0 and sv2v do (verilator 5.052 writes 0), and W4028 quotes the view, `invalid decimal value "\xEF\xBF\xBD" in a matched plusarg`, where iverilog quotes the byte (`"\xA9"`) (Q-STRBYTES r1 review cell s04 P1, pinned `l_s04_plus_moves`)
* fix: argv through `args_os`, a `+plusarg` kept as bytes (unix `OsStrExt`), any other non-UTF-8 argument a CLI error (exit 3), staged `vrun` the same, the numeric conversion and W4028's quote read the bytes
