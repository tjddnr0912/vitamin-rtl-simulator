(§5.2 Q-ESCTDKEEP · rank ②) (an escaped type name holding `::` escapes its module):
* an escaped type name holding `::`, declared in a module, escapes the module: the unit-end restore keeps every `::`-spelled slot the unit added, as a package twin (`hdl-parser/src/type_rec.rs:395–419` `unit_kept`; before §4.5.631 `scope.rs` `restore_scope_unit`, per map), and `ident()` (`lib.rs:1303–1307`) names a declaration by its raw text, so `module m1; typedef logic [7:0] \q::t ; endmodule` leaks into the next module: `module top; \q::t  v;` runs `A e01 v=a5 b=8` where iverilog 13.0 (`syntax error`) and verilator 5.052 (`Can't find typedef/interface: 'q::t'`) refuse
* symptom: under a unit `typedef logic [7:0] \q::t ;` a module-local 6-bit packed struct of that name replaces the unit's: `$bits(\q::t )` `A e05 v=a5 bt=6 bv=8` (e05; iverilog and verilator `A e05 v=a5 bt=8 bv=8`), an alias `typedef \q::t  w_t;` `bw=6` (e07; both `bw=8`), and a module-local record `\q::r ` makes the unit's vector variable undeclared, E3010 `undeclared net/variable top.v` (e12; verilator `A e12 v=5a b=8`, iverilog `sorry: Unpacked structs not supported`)
* fix: keep a unit's package twins by origin (the endpackage write), not by spelling
